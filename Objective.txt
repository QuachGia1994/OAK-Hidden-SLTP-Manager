## Lỗi chính còn lại 🔴

### Dev mode không truyền `--profile` cho signal bot

Trong `start_signal_process()`, nhánh dev hiện là:

```python
cmd = [sys.executable, "-u", script]
```

Không thấy append `--profile <profile>` cho `signal_bot`.  Sau đó code đem `cmd` vào `subprocess.Popen()` luôn, không có đoạn bổ sung profile phía dưới.

Nghĩa là chạy từ source bằng GUI thì `mt5_signal_bot.py` vẫn không nhận profile đang chọn. Nó sẽ fallback vào profile đầu tiên trong `profiles.json`. Trong `mt5_signal_bot.main()`, nếu không có `profile_name`, nó đọc `profiles.json` và lấy key đầu tiên.

**Fix cần thêm ngay:**

```python
if not getattr(sys, "frozen", False):
    cmd = [sys.executable, "-u", script]
    if key == "signal_bot":
        profile = self.combo_profiles.get() if hasattr(self, "combo_profiles") else ""
        if profile:
            cmd.extend(["--profile", profile])
```

## Lỗi phụ cần dọn 🟡

### 1. `mt5_signal_bot` chưa validate profile

Prompt yêu cầu nếu profile không tồn tại thì warning và fallback an toàn. Nhưng code hiện chỉ set `_active_profile = profile_name` nếu có profile truyền vào, chưa thấy validate profile đó có trong `profiles.json`.

### 2. Migration token chỉ chạy khi không truyền profile

Trong cùng đoạn đó, `migrate_plaintext_tokens(_profiles_data)` nằm trong nhánh `else`, tức chỉ chạy khi không có `profile_name`. Nếu chạy signal bot bằng `--profile`, migration có thể không chạy.

Nên đổi thành: luôn đọc `profiles.json`, luôn migrate nếu cần, sau đó chọn profile theo thứ tự `CLI profile > first profile`.

### 3. Test command chưa test function thật

`tests/test_command_construction.py` tự tạo command mẫu trong test, ví dụ `cmd = [sys.executable, "-u", "mt5_signal_bot.py", "--profile", profile]`, chứ không gọi `start_signal_process()` hoặc helper build command thật. Vì vậy test pass nhưng code thực tế vẫn thiếu `--profile` ở dev mode.

`tests/test_signal_bot_profile.py` cũng mới test argparse cơ bản, chưa test `mt5_signal_bot.main()` có giữ profile hay không.
