# OAK workspaces
> updated 2026-09-25 · v4.2.0

The six-screen concept defines visual hierarchy; live prices, dates, cards and AI results always come from the existing product.

## Routes and contracts
- /engine: unified Live + retained-history broker-day matrix with one XAUUSD-owned `ENTRY TIME` row plus five visible signal rows: XAUUSD/GBPUSD/AUDUSD/USDCAD/USDJPY across H3/H6/H9/H12/H14; H16 is removed. Rule v90 keeps the exact same-broker-day own-symbol M15 base at `entry time - 2h15` (entry H11 therefore reads 08:45). XAUUSD/GBPUSD/AUDUSD keep that intrinsic base signal, USDCAD/USDJPY invert it, then a final H3 selector applies: H3/H6/H9 use the previous available broker day's XAUUSD H3 Entry (`H4` keep, `H5` invert), while H12/H14 use today's XAUUSD H3 Entry with the same H4/H5 rule. Missing selector evidence yields no final signal. Evidence distinguishes the XAUUSD entry pattern, exact signal-base OHLC, intrinsic row rule and H3 selector; schema 18/state v56 remain stable and retained History is rebuilt from local ICMarkets M15.
- /history: compatibility route only; redirects to `/engine`, where the same Sunday-first retained-date calendar is available as a compact popover.
- /neotech: public C5 helper v1.09 is standalone-first. The page leads with a one-click Windows Setup that embeds the verified EX5 and detects MT5 data folders, while direct EX5 + checksums remain available. Local C5 popup and chart `C5 LOOK` need no Telegram, Node, PowerShell command, bootstrap, token, login input or WebRequest; account identity auto-binds across MT5 switches. Existing OAK Telegram forwarding is optional and full controller provisioning sits under Advanced/Operator. The 14-rule evaluation workspace remains separate and unchanged.
- /tools: three localized tool cards backed by the shared OAK_TOOLS catalog. Their Fact Check, Tarot and Discover motifs are rendered by one shared Three.js renderer using scissor viewports, with the existing illustrated artwork retained as the fallback. Cards sit side by side on desktop and stack on smaller screens.
- /factcheck: text/link and image drafts survive mode switches. OCR returns editable text; image analysis preserves origin, generation, manipulation and completeness. The hero adds a Three.js Evidence Lens while the form/results remain DOM. Public sharing and backend handlers are unchanged.
- /tarot: compact question and one/three-card controls beside the real 78-card deck on desktop and above it on mobile. A Three.js deck hero is decorative only; drawn Rider-Waite artwork is mapped onto render-on-demand 3D result cards with the original image retained as fallback. Decorative backs never replace the server draw. AI failure still preserves drawn cards.
- /discover: Daily across the top, then Dream/Oracle and Mood/Compatibility. One shared Three.js constellation reacts to whichever of the five experience sections is most visible instead of opening five WebGL contexts. Daily, Oracle and Mood stay local; only Dream/Compatibility call AI.

## Presentation owners
- globals.css owns semantic tokens and workspace width. All six workspaces (/engine, /neotech, /tools, /factcheck, /tarot and /discover) share graphite/mint through route-scoped command palette tokens. Shared-report and account routes retain their existing palette. Light and contrast remain available.
- oak-redesign.css owns navigation, WorkspaceHeading, ToolArtwork, workspace layout and image-input composition. Replaced367old selectors before adding the canonical rules. factcheck-share.css retains report/share semantics; overlapping image-input declarations were moved to their composition owner.
- EngineCore owns the localized /engine heading, saved-feed status, publication time and metadata. EngineSignalCore owns the hero's Three.js signal-core visualization and keeps OrbitBrandMark as the no-WebGL fallback; reduced motion is static, hidden/offscreen rendering pauses, mobile lowers rendering cost, and the visualization never represents order execution or profit. OakThreeStage applies the same lifecycle contract to NeoTech, Fact Check, Tarot and Discover, while ToolsThreeStage uses one renderer for all three directory cards; every stage renders one initial frame before exposing `ready` so background tabs cannot hide their fallback prematurely. Missing data remains explicit. H1EngineBoard retains the existing signal table and adds links to NeoTech and broker accounts. ToolsClient owns the localized tools directory heading and cards in tools.module.css; NeoTechPublicDashboard owns its rule workspace in neotech.module.css. Fact Check, Tarot and Discover each own a scoped workspace stylesheet beside their components. Fact Check has an illustrated heading and text/image workbench; Tarot places its question form beside the deck on desktop; Discover features Daily above its other four experiences and reuses WorkspaceHeading. NavBar uses the real oak-app-icon.png and OAK GATEKEEPER wordmark. Mobile has three direct tabs; desktop retains a keyboard-operable tools menu. Directory links use flex layout, never the icon/detail grid.
- ToolArtwork's finite kind maps to one generated transparent3x3atlas, dashboard/public/oak-workspace-atlas-v2.webp (489488bytes, SHA256 df9d9969b7e9fe908123ea053ebf7867490461413454dfef870308fb9db7fa73). Built-in ImageGen prompt: premium luminous navy/cyan/violet/gold painterly3D sprite sheet; photo+magnifier, fanned tarot, compass; mountain sunrise, crescent clouds, oracle sphere; crystal hearts, ornate single card back, night clouds. No text, labels or data. WebP is a format conversion of the generated original. This is concept-directed new artwork, not pixel-identical extracted art.
- Browser follow-up removed legacy HUD glass overrides from workspace panels, restored cyan borders, fitted all six H1 columns at393px (native pan retained at320px), and reduced Discover mobile header/form height. Tarot backs use centered artwork within the deck panel.
- H1EvidencePanel retains its dialog variant with focus trapping; inline variant is a normal region. Copy chart uses the same renderer.
- /workspace-review.html is a noindex visual QA harness: same-origin real pages at320/393/768/1100px widths. It introduces no mock data or API. This tests responsive layout in Chromium, not iOS Safari engine behavior.
